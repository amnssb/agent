# 扩展开发与依赖姿势

每个扩展放在 `extensions/<名字>/` 下，由 `manifest.json` 声明身份、入口与 CLI 挂载。

## 扩展间依赖与降级姿势

本仓库后端 `ctx` 提供 `patch` / `op` / `onDispose`，前端 `app` 提供注册槽位与 `onDispose`，不提供跨扩展 `use()` 服务总线。处理依赖和槽位时按下面三类选型：

| 场景 | 做法 | 说明 |
| --- | --- | --- |
| 必需依赖 | 在 `manifest.json` 写 `requires: ["xxx"]` | 加载器按拓扑顺序启动，依赖缺失、未启用或停用时自动级联停用 |
| 可选增强 | 不写 `requires`，运行时检测后降级 | 例如按需检查目标模块/配置是否存在，缺失时跳过增强而不阻塞启动 |
| 界面槽位 | 使用可选链（如 `app.topbar?.add(...)`） | 目标宿主槽位不存在时静默不挂，保持与旧版宿主或精简界面的兼容 |

## 权限声明（仅设置页展示）

`manifest.json` 可选声明 `permissions: string[]`，在「设置 → 扩展」中告知用户该扩展会触及哪些能力。**该字段仅作展示说明，不做运行时沙箱拦截**；模型工具调用仍走统一的权限规则与审批关口。

常用标识：`tools`（注册工具）、`admin-ops`（管理接口）、`session-read`（读会话）、`fs-read`（读文件）、`fs-write`（写文件）、`process`（后台调度/进程）、`ui`（界面扩展）。自定义扩展也可填写其他说明字符串，设置页会原样展示。
